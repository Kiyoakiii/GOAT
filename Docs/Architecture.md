# Архитектура GOAT — карта проекта

Документ для человека: что где лежит, как работает, что крутить, что не трогать.
Актуален для структуры после рефакторинга (asmdef на каждую папку внутри `Assets/GoatDescent/`).

---

## 1. Модель проекта: одна игра, несколько локаций

Игра строится как набор **локаций-сцен в единой визуальной стилистике**:

| Локация | Статус | Где живёт |
|---|---|---|
| **Гора с трассой** — спуск по процедурной горе, ядро геймплея | Основная, готова | `Assets/GoatDescent/` (Terrain + Bootstrap + Route + Decor + Player) |
| **Туманные столбы** (Vista / pillars) | Эксперимент будущей локации | `Assets/GoatDescent/Vista/` |
| Биомный мир 2×2 км (Procedural World) | Лаборатория внутри Vista | `Assets/GoatDescent/Vista/` |
| Новые локации | Будущее | Добавляются по чеклисту из раздела 7 |

Единая стилистика держится не на папках, а на **общих слоях**, которые все локации переиспользуют:
шейдеры `GoatDescent/*`, текстуры, материалы горы, физика поверхностей и одна и та же фабрика козы
(подробнее — раздел 6). Новая локация = новая сцена + свой builder-скрипт поверх этих слоёв.

## 2. Быстрый старт

**Играть:** открыть сцену `Assets/GoatDescent/Scenes/GoatPlayground.unity` → Play.
Сцена почти пустая (~10 объектов) — весь мир (гора, трасса, декор, козлы) строится кодом
при запуске скриптом `MountainSceneBuilder`. Это единственная сцена в Build Settings.

**Крутить гору:** окно **Tools → GOAT → Mountain Editor** — все настройки формы, трассы и декора
с живым превью (пересборка через 0.3 с после изменения ползунка). Настройки хранятся в
EditorPrefs и переживают перезапуск Unity.

**Открыть лабораторию столбов:** сцена `Assets/GoatDescent/Vista/Scenes/ProceduralWorldMilestone.unity`
(26 запечённых столбов). Полигон одного столба: `Assets/GoatDescent/Scenes/Testing/SinglePillarPlayground.unity`.
Инструмент генерации: **Tools → Procedural World → Open Generator**.
Эти сцены **не** входят в Build Settings — это песочница, в игру они не попадают.

## 3. Игровая гора: конвейер «настройки → трасса → гора»

Ключевая идея, из-за которой всё устроено именно так: **сначала генерируется трасса, гора строится вокруг неё**.
Не «на гору выкладываем путь», а «путь приказывает горе, где сделать полки».

```
MountainEditorWindow (настройки, EditorPrefs)
  │  RebuildTerrain() / BuildWorld() при старте сцены
  ▼
MountainRoute.Generate            — спираль трассы от вершины к подножию:
  │                                 площадки с типами (Rest, Grip, Precise, Ice, Crumbling),
  │                                 секции-паттерны (Spiral/Zigzag/Traverse/Wall/Leap/Scree),
  │                                 ветки-обходы, окна ветра
  ▼
TerrainHeightField                — гора подстраивается под трассу:
  │                                 под площадкой — плоская полка, вокруг — провал,
  │                                 под осыпающейся платформой — воронка;
  │                                 базовый силуэт: warp + асимметрия + кулуары +
  │                                 террасы + ridged-шум + эрозия + осыпи
  ▼
TerrainMeshBuilder                — меш горы + вершинные цвета (маска платформ и
  │                                 прогресс трассы — их читает шейдер для подсветки)
  ▼
MountainDecor.Generate            — деревья/кусты/камни/цветы/трава по правилам
  │                                 (уклон, высота, «вне трассы»)
  ▼
MountainRouteProps.Generate       — пропсы трассы: ледяные плиты, осыпающиеся
  │                                 платформы (Rigidbody), ветровые триггеры
  ▼
Спавн козлов                      — пара A/B на нулевой площадке (вершина),
                                    лицом к следующей; старт = route[0]
```

Входная точка — `Bootstrap/MountainSceneBuilder.BuildWorld()`. Он же собирает окружение:
туман, процедурное небо, солнце, камеру, сессию. `RebuildTerrain()` пересобирает только
гору+декор+пропсы (козлов не трогает).

**Спуск = прогресс 0→1 вниз по трассе** (`Player/RouteProgressTracker`): чекпоинты на Rest-площадках,
R — респавн на чекпоинт, Backspace — на вершину.

### Шпаргалка ползунков Mountain Editor

**Площадки (главное)** — это настройки трассы:
- *Число площадок* (6–100) — плотность трассы;
- *Дальность прыжка* (3–12) — макс. разрыв между площадками;
- *Размер уступа* (2–8) — радиус площадки, м;
- *Провал между* (0–6) — глубина ямы вокруг уступа (визуальная читаемость прыжка);
- *Сложность* (0–1) — открывает типы площадок (лёд, осыпающиеся, точные) и сложные паттерны, укорачивает разрывы;
- Тумблеры: ветки, типы площадок, ветер, респавн по чекпоинтам.

**Размер**: радиус основания (30–500), высота вершины (80–600), высота долины (−50…50), плотность сетки меша (64–320).

**Форма** — силуэт горы:
- *Кулуары* (0–10) — вертикальные жёлобы по склонам;
- *Пояса* (3–30) — террасирование высоты («слоёность»);
- *Искривление* (0–60) — доменное искажение контура, ломает правильность конуса;
- *Отроги* (0–40) — асимметричные выступы по азимуту;
- *Шероховатость* (0–12) — мелкий шум поверхности;
- *Смещение вершины*, *Вытянутость* — сдвиг пика и эллипсность массива;
- *Скалистость гребней* (0–0.4) — острый ridged-шум, сильнее к вершине;
- *Эрозия* (0–2) и *Осыпи* (0–2) — «геологическое» сглаживание склонов (капельная модель + перенос материала);
- *Сид* — всё детерминировано от него; кнопка «Случайная гора» = новый сид.

**Декор**: счётчики кустов (0–800), деревьев (0–700), камней (0–400), цветов (0–1000), травы (0–2500).

Часть констант ещё захардкожена в коде (см. раздел 8 «Где живёт внешний вид» и раздел 10).

## 4. Лаборатория Vista (pillars)

`Assets/GoatDescent/Vista/` — автономный модуль-песочница. В игровую сцену и билд **не входит**.
Два подмодуля:

**Misty Pillars** — виста «туманный лес на песчаниковых столбах»:
- `Runtime/MistyPillarsVistaBuilder.cs` — строит 26 столбов (7 передних + 19 фоновых) с лесом на вершинах; у каждого свой сид и один из 4 силуэтов (Classic/Spire/Mesa/Leaning); столб с сидом 21 — всегда спавн-столб с поляной;
- `Runtime/PillarMeshBuilder.cs` — процедурные меши (скала, кроны, ветки);
- запекание мешей в ассеты: **Tools → Procedural World → Apply Misty Pillars Vista** → `Vista/Generated/MistyPillars/`;
- в сцене Milestone коза может спавниться по маркеру `Pillar Goat Spawn`.

**Procedural World** — биомный мир 2048×2048 м на Unity Terrain (высоты, биомы Coast/Meadows/Forest/Mountain, снег, вода, чанки, деревья из Blender-пака):
- окно **Tools → Procedural World → Open Generator**; все кнопки генерации запускают общий конвейер `GenerateWorld`;
- требует Blender-пак моделей в `Assets/Art/Generated/` (см. раздел «Модели мира» в README).

Отдельный полигон: `SinglePillarPlayground` — один столб + оранжевая summit-платформа.

Vista имеет **собственные копии** шума и генератора рельефа (`NoiseGenerator`, `BiomeGenerator`) —
это осознанное дублирование лаборатории, не «вторая актуальная система». Не путать с Terrain.

## 6. Модули `Assets/GoatDescent/`

| Папка | Что это | Ключевое | «Крутить здесь» |
|---|---|---|---|
| `Bootstrap/` | Сборка игровой сцены | `MountainSceneBuilder` (BuildWorld/RebuildTerrain), `GoatSpawner` | Порядок сборки мира, свет, туман, небо |
| `Terrain/` | Ядро горы | `MountainGenerator` (фасад), `MountainRoute` (трасса), `MountainSettings` (параметры), `TerrainHeightField` (высоты+полки), `TerrainNoise`, `MountainErosion`, `TerrainMeshBuilder`, `MountainMaterial` | Форма и цвет горы (но крутить лучше через окно редактора) |
| `Terrain/Shaders/` | Шейдеры | `MountainShader` (зонирование снег/трава/скалы, подсветка трассы), `SkyShader` (процедурное небо), `PostProcessShader` (цветокор) | Визуальный стиль |
| `Route/` | Пропсы трассы | `MountainRouteProps` (расстановка), `WindGust` (порывы ветра) | Поведение опасностей |
| `Decor/` | Растительность/камни | `MountainDecor` (правила размещения), `DecorMeshLibrary`, `DecorMaterials` (плоские цвета) | Количество/вид декора |
| `Player/` | Коза и её механики | `GoatController`, `GoatGripController`, `GoatSlopeBalance`, `ThirdPersonGoatCamera`, `CinematicPostProcess`, `CrumblingPlatform`, `RouteProgressTracker`, `RespawnController`, `GoatPlayerFactory` | Управление, физика козы |
| `Vista/` | Лаборатория (раздел 4) | Столбы + биомный мир | Эксперименты локаций |
| `Editor/` | Инструменты редактора | `MountainEditorWindow` (Tools → GOAT), все `*CI` — batch-точки входа | UI настроек, проверки |
| `Scenes/` | Сцены | `GoatPlayground.unity`, `Testing/` | — |
| `Textures/` | CC0-текстуры | rock/grass/dirt + normal; грузятся в рантайме из файлов | Замена текстур |

Каждая папка — отдельная asmdef; зависимости однонаправленные: Vista → Terrain/Player, внутри игры Bootstrap/Terrain/Route/Decor/Player связаны через общие модули.

## 7. Чеклист: добавить новую локацию

По образцу Vista (столбы) — новая локация = сцена + builder поверх общих слоёв:

1. **Сцена**: пустая сцена в `<Модуль>/Scenes/` или `Scenes/Testing/`. В Build Settings не добавлять, пока локация не станет игровой.
2. **Builder**: MonoBehaviour-скрипт, который при старте (или по кнопке в Inspector) строит локацию:
   - меши — процедурно (образец: `MistyPillarsVistaBuilder`) или статикой;
   - материалы — через общие (`MountainMaterial.Load`, `DecorMaterials`), не плодить свои копии;
   - в конце — спавн козы: `GoatPlayerFactory.Create` (образец: `MistyPillarsSceneController`) или маркер `Pillar Goat Spawn` + `GoatSpawner`.
3. **Поверхность**: если локация «лазабельна» — добавить `MountainSlopeSurface` на коллайдеры, чтобы зоны поверхности/сцепление работали одинаково.
4. **CI-точка**: `*CI.cs` в `Assets/GoatDescent/Editor/` по образцу `SinglePillarCI`/`VistaRegenCI` — открыть сцену, проверить инварианты, при необходимости перегенерировать.
5. **Единство стиля**: небо — `GoatDescent/Sky`, туман — RenderSettings, цветокор — `CinematicPostProcess` на камере. Тогда новая локация автоматически «та же игра».

## 8. Где живёт внешний вид (для стилизации)

Основные визуальные параметры вынесены в окно **Tools → GOAT → Mountain Editor**, группа
**«Стиль (внешний вид)»**: туман, солнце, ambient, небо, зоны краски (снег/трава/крутизна),
размер текстур, постобработка. Кнопки-пресеты: **Valheim** (мягкий туманный стиль, по умолчанию)
и **Базовый** (прежний нейтральный вид). Хранение настроек то же — EditorPrefs.

Код, который применяет эти параметры:

| Что | Где |
|---|---|
| Туман, ambient, небо, солнце | `Bootstrap/MountainSceneBuilder.cs` (`SetupEnvironment`, `ApplySun`) |
| Параметры краски горы → шейдер | `Terrain/MountainMaterial.cs` (`Configure`) |
| Низкораставые текстуры + процедурный снег | `Terrain/MountainMaterial.cs` (`Load`, `CreateSnowTexture`) |
| Виньетка, тёплые света/холодные тени | `Player/CinematicPostProcess.cs` (`Apply`) + `Terrain/Shaders/PostProcessShader.shader` |
| Подсветка трассы | `Terrain/Shaders/MountainShader.shader` (`_HighlightTrack`) |
| Цвета декора | захардкожены в `Decor/DecorMaterials.cs` |
| Константы эрозии/осыпей | захардкожены в `Terrain/MountainErosion.cs` |

## 9. Осторожно: известные мины

1. **killPlane −12 м захардкожен** (`Player/RespawnController.cs`) при высоте долины по умолчанию −6. Подняли долину выше −12 — козёл умирает при касании земли; опустили сильно ниже — падает «в бесконечность» (пол меша кончается на ValleyY−40).
2. **Два механизма спавна козлов**: `MountainSceneBuilder` спавнит пару A/B, `GoatSpawner` ищет маркер `Pillar Goat Spawn`. Смешать оба в одной сцене — получить 1 или 3 козлов.
3. **RebuildTerrain в play-режиме** не обновляет трассу у живых козлов (`RouteProgressTracker` держит старый список): чекпоинты, прогресс и подсветка разъедутся с новой горой.
4. **Статическое состояние**: `RouteQueries` и статики `TerrainHeightField` — одна гора на процесс. Два билдера/превью одновременно конфликтуют.
5. **Строковые связи**: имена объектов `"Procedural Mountain"`, `"Mountain Surface"`, `"Route Markers and Hazards"`, маркер `"Pillar Goat Spawn"` ищутся по имени — не переименовывать.
6. **Сгенерированные каталоги** (`Assets/Art/Generated/`, `Assets/GoatDescent/Vista/Generated/`) в `.gitignore`, пересоздаются скриптами/CI. Вручную не править и не коммитить.
7. **Магические константы, связанные между модулями**: офсет площадки над рельефом 1.2 м (осыпающиеся — 0.15), воронка под crumbling −1.35, ширина ледяной плиты ×1.9, порог обвала 95 кг — менять синхронно или через один источник.
8. **Batch-проверки** (компиляция, шейдеры, CI-методы) — только при закрытом Unity; команды и точки входа в корневом `AGENTS.md`.
9. **`Docs/ProjectState.md`** — исторический снимок от 29.09.2026 (до рефакторинга): пути из него устарели, использовать эту страницу.
